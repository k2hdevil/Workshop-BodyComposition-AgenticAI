# 샘플 체성분 분석 결과지

> **본 데이터는 전부 가상의 합성 데이터입니다.**
> 실제 인물·기관·측정기기와 무관하며, 교육 및 소프트웨어 테스트 목적으로만 사용합니다.
> 기재된 성명은 가명이고, 측정기기명(`BodyScan Pro 970`)은 가상의 모델명입니다.

## 상표 관련 주의

"인바디"는 (주)인바디의 등록 상표입니다. 본 저장소는 교재·코드·파일명·앱 이름 어디에도
해당 상표를 쓰지 않고 일반명 **체성분 분석(body composition analysis)** 을 사용합니다.
실제 제조사 결과지를 다룰 때는 기기명 필드에 해당 제조사명이 들어온다는 점만 참고하세요.

```
sample-data/
├── ground-truth/           정답 데이터 (단일 원본, git 추적)
│   ├── user-a-session-01.json
│   ├── user-a-session-02.json
│   ├── user-a-session-03.json
│   └── user-b-session-01.json
├── pdf/                    참가자 배포용 결과지 (git 추적)
│   └── (위와 같은 이름의 .pdf 4건)
├── html/                   중간 산출물 (git 미추적, 재생성 가능)
└── tools/
    ├── render_sheet.py     JSON -> HTML 결과지
    ├── make_scan.py        텍스트 PDF -> 이미지 전용 스캔본
    ├── build_samples.sh     전체 빌드
    └── verify_samples.py    산수 정합성 + PDF 대조 검증
```

### JSON이 단일 원본입니다

PDF와 정답 데이터를 각각 손으로 작성하면 반드시 어긋나고, 그러면 Ground Truth가 아니라
버그가 됩니다. 이 저장소는 **`ground-truth/*.json` 하나만 사람이 작성**하고 PDF는 거기서
렌더링합니다. 값을 고치려면 JSON만 고치고 빌드를 다시 돌리세요.

| 문서 | 인물 | 측정일 | 형식 | 역할 |
|------|------|--------|------|------|
| `user-a-session-01` | 김도현 44세 남 | 2026-02-14 | **스캔본 (이미지 전용)** | 추이 기준선. 비만 최악 상태 |
| `user-a-session-02` | 김도현 | 2026-05-16 | 디지털 출력본 | 개선 진행 중 |
| `user-a-session-03` | 김도현 | 2026-08-14 | 디지털 출력본 | 최근. 델타 분석 대상 |
| `user-b-session-01` | 박지은 32세 여 | 2026-08-18 | 디지털 출력본 | **다른 사용자.** 저체중, D자형 함정 |

### user-a — 6개월 추이

| 지표 | 1회차 | 2회차 | 3회차 | 변화 |
|------|-------|-------|-------|------|
| 체중 (kg) | 96.6 | 94.2 | 92.4 | **−4.2** |
| 체지방량 (kg) | 34.0 | 31.8 | 30.0 | **−4.0** |
| 골격근량 (kg) | 34.9 | 34.8 | 34.8 | **−0.1** |
| 체지방률 (%) | 35.2 | 33.8 | 32.5 | −2.7 %p |
| BMI | 31.7 | 30.9 | 30.3 | −1.4 |
| 내장지방레벨 | 18 | 17 | 15 | −3 |
| 체성분점수 | 62 | 65 | 68 | +6 |

감량분 4.2kg 중 4.0kg이 체지방이고 골격근 손실은 0.1kg입니다. **근손실 없는 양질의 감량**이라
운동·식단 에이전트가 "현재 방향을 유지하라"고 판단해야 하는 케이스입니다. 다만 목표까지
19.0kg이 남았고 현재 페이스(월 −0.7kg)로는 약 27개월이 걸립니다.

## 각 문서에 심어둔 테스트 포인트

### 1. 스캔본 — 추출 폴백 경로 (`user-a-session-01`)

텍스트 레이어가 **0자**입니다. `pdfplumber` 같은 구조 파서로는 아무 값도 나오지 않으므로,
추출 도구가 비전 경로로 폴백하지 않으면 이 문서에서 실패합니다.
그레이스케일 + 0.35도 기울기 + 스캐너 노이즈까지 재현되어 있습니다.

**실측 결과** (`tools/verify_vision_fallback.py`, us-east-1):

| 항목 | 결과 |
|------|------|
| Bedrock Converse document 블록으로 읽히는가 | **읽힘. `citations` 설정 불필요** |
| 처리 경로 | 페이지 이미지 (입력 1,654 토큰 / 텍스트 PDF 는 3,181 토큰) |
| 측정 수치 정확도 | 6/6 정확. 부위별 근육 표도 소수 2자리까지 5/5 정확 |
| 성명 | **`김도현` → `김도원` 오독. temperature=0 에서 5/5회 재현** |

두 가지가 여기서 확정됐습니다.

1. **래스터화 라이브러리가 필요 없습니다.** PyMuPDF·poppler·Code Interpreter 없이
   순수 Python + Converse 만으로 스캔본을 처리할 수 있습니다.
2. **한글 이름은 신뢰할 수 없습니다.** 숫자는 형태가 뚜렷해 정확하지만 `현`/`원` 처럼
   획 하나 차이인 음절은 체계적으로 틀립니다. 그래서 결과지 이름으로 본인 확인을 할 때
   문자열 완전일치를 쓰면 안 됩니다 (아래 4번 참고).

### 2. D자형 함정 (`user-b-session-01`)

체형 판정은 **D자형**입니다. D자형의 교과서적 설명은 "근육이 많고 지방이 적은 이상적 상태"입니다.
그런데 이 문서는 표준 대비 백분율이 **셋 다 100% 미만**입니다.

```
체중     81.6 %
골격근량 86.5 %   <- 체중보다 높음 -> 형태상 D자형
체지방량 62.8 %
```

형태만 보고 "이상적 체형입니다"라고 답하면 오판입니다. 실제 소견은 저체중 + 전신 근육량 부족이고,
권고 방향이 user-a와 **정반대(증량)** 여야 합니다. 에이전트가 형태 패턴에 낚이는지 검증하는 장치입니다.

### 3. 상하 불균형 (`user-a` 전 회차)

부위별 근육에서 몸통은 표준 이상(110.8%)인데 하지는 표준 하단(평균 98.3%)입니다.
운동 에이전트가 이걸 읽어내 **하체 강화**를 제안해야 합니다.

### 4. 다른 사용자 (`user-b`)

`subject_id`가 `user-b`로 user-a와 다릅니다. Memory 격리, 본인 확인(로그인 사용자 ↔ 결과지 이름
대조), 접근 제어를 검증하는 데 사용합니다.

본인 확인은 **문자열 완전일치로 판정하지 않습니다.** 위 1번에서 확인했듯 스캔본의 한글 이름이
체계적으로 오독되므로, 완전일치로 차단하면 정당한 사용자가 막힙니다.

| 판정 | 처리 | 이 샘플로 재현되는 케이스 |
|------|------|------------------------|
| 완전일치 | 통과 | user-a 로 로그인 + `user-a-session-02` 또는 `-03` |
| 편집거리 1 이하 | 경고 후 진행 | user-a 로 로그인 + `user-a-session-01` (스캔본, 김도원으로 오독) |
| 그 외 | 차단 | user-a 로 로그인 + `user-b-session-01` (박지은) |

세 경우가 샘플 4건으로 모두 재현됩니다. Lab 1 의 검증 시나리오로 그대로 쓸 수 있습니다.

## 데이터 스키마

각 측정 항목은 아래 형태입니다. 추출 도구가 만들어야 하는 목표 구조이기도 합니다.

```json
{ "value": 30.0, "std_low": 6.7, "std_high": 13.4, "flag": "HIGH", "label_ko": "체지방량" }
```

`flag`는 표준범위 비교 결과입니다.

| 값 | 의미 | 사용처 |
|----|------|--------|
| `LOW` / `NORMAL` / `HIGH` | 표준이하 / 표준 / 표준이상 | 체성분·비만 분석 |
| `BELOW` / `NORMAL` / `ABOVE` | 표준이하 / 표준 / 표준이상 | 부위별 근육 (95~105%를 표준으로 봄) |

최상위 키는 다음과 같습니다.

| 키 | 내용 |
|----|------|
| `subject` | `subject_id`, 성명, 나이, 성별, 신장 |
| `measurement` | `session_seq`, 측정일시, 기기, 측정방식 |
| `reference` | 표준체중 / 표준 골격근량 / 표준 체지방량 / 성별 체지방률 표준 |
| `body_composition_analysis` | 체수분·단백질·무기질·체지방량 + 세포내외수분 + 제지방량 |
| `muscle_fat_analysis` | 체중·골격근량·체지방량의 표준 대비 % + 체형 판정 |
| `obesity_analysis` | BMI, PBF + 비만 단계 |
| `segmental_lean_analysis` | 5개 부위 + 좌우/상하 균형 |
| `additional_metrics` | 복부지방률, 내장지방레벨, 기초대사량, 체성분점수 |
| `control_guide` | 적정체중, 체중·근육·지방 조절량 |
| `expected_analysis_findings` | 분석 에이전트가 도달해야 하는 소견 (평가 기준) |
| `expected_trend_vs_session_01` | 추이 델타 정답 (3회차에만 존재) |

`expected_*` 필드는 결과지에 인쇄되지 않습니다. **Lab 7 평가에서만 사용하는 정답**입니다.

## 재생성

```bash
cd sample-data
./tools/build_samples.sh      # JSON -> HTML -> PDF -> 스캔본
python3 tools/verify_samples.py
```

`build_samples.sh`는 macOS의 headless Chrome을 사용합니다. Chrome은 `--print-to-pdf` 작업을
끝낸 뒤에도 프로세스가 종료되지 않는 경우가 있어(Chrome 151 확인), 스크립트가 출력 파일 크기가
안정되는 시점을 성공으로 판정한 뒤 **해당 인스턴스만** 정리합니다. 전용 임시 프로필을 쓰므로
사용자가 열어둔 Chrome은 영향받지 않습니다.

필요 패키지: `pdfplumber`, `PyMuPDF`, `Pillow`

## 검증 항목

`verify_samples.py`는 문서 4건에 대해 **158개 검사**를 수행합니다.

**산수 정합성** — 결과지 수치는 서로 종속됩니다. 하나만 고치면 조용히 어긋나므로 불변식으로 막습니다.

```
체수분 + 단백질 + 무기질 + 체지방량 = 체중
제지방량 = 체수분 + 단백질 + 무기질
세포내수분 + 세포외수분 = 체수분
세포외수분비 = 세포외수분 / 체수분
BMI = 체중 / 신장(m)²
체지방률 = 체지방량 / 체중 × 100
표준대비(%) = 측정값 / 표준값 × 100
기초대사량 = 21.6 × 제지방량 + 370
근육조절 + 지방조절 = 체중조절
적정체중 = 체중 + 체중조절
부위별 합 < 제지방량        (머리 등 비분절 부위 제외)
```

**판정 일관성** — `flag`가 표준범위와 모순되지 않는지, 체형 판정(C/I/D)이 세 막대의 형태와
맞는지 재계산으로 확인합니다.

**추이 정합성** — `expected_trend_vs_session_01`의 델타가 실제 회차 간 차이와 일치하는지 확인합니다.

**PDF 대조** — 디지털 출력본은 정답 값 11개와 4개 섹션 제목이 텍스트로 추출되어야 하고,
스캔본은 추출되는 텍스트가 **0자**여야 합니다. 그리고 모든 문서는 **1페이지**여야 합니다.
