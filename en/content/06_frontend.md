## Theory: Why ECS Express Mode, and What Is the Token Boundary (7 min)

### Frontend deployment target: ECS Express Mode

Serving Streamlit over HTTPS needs a managed deployment. **AWS App Runner has stopped accepting new
customers** (the temporary workshop accounts are new accounts, so it is unavailable), so you use **Amazon ECS
Express Mode** instead. Given a single container image, it configures a Fargate service, a load balancer (SSL/TLS),
autoscaling, and a unique URL for you.

| Item | ECS Express Mode |
|------|------------------|
| Input | **Container image** + 2 execution roles |
| Configured automatically | Fargate service, ALB (HTTPS), autoscaling, URL |
| URL format | `https://<service-name>.ecs.us-west-2.on.aws/` |
| Price | No charge for Express itself (only Fargate, ALB, CloudWatch, and data transfer) |

> **Use a container for the frontend only.** The agent Runtime stays on **CodeZip**, as decided in Lab 5
> (a Docker build is the point where the 4-hour session is most likely to fail). The frontend containerizes
> only a single thin Streamlit app (a 6-line Dockerfile), so one ECR push is enough.

### `st.login()` uses the authorization code flow

`st.login()` in Streamlit 1.42+ redirects to Cognito and handles the login. The callback path
**must end with `/oauth2callback`** (the callback URL of the pre-provisioned Cognito App Client
is set up to follow this rule).

### The screen gets the name, the agent gets the token

Finish the boundary design (README) at the screen level.

| What | Where from | Handling |
|------|--------|------|
| User name | Cognito profile | Shown **on screen only** |
| Access token | `st.user` | Used for the Gateway call |
| Name on the result sheet | Extraction result | **Compared only** against the login name (identity check) |

### The Gateway requires an access token

An ID token gets a 403 (`insufficient_scope`). By default no token is exposed, so you must put `"access"` in
`expose_tokens` in `secrets.toml` before you can take the token.

> **Caution (needs re-confirmation)**: We have not yet measured in a browser flow whether the access token
> (`scope: openid email profile`) issued by the `st.login()` authorization-code flow passes the Gateway.
> What we confirmed with the CLI is the `admin-initiate-auth` token. If it does not pass, bypass the Gateway
> call by going through the Runtime. The login, upload, and screen parts of this Lab proceed unchanged.

### Step 3: Upload + identity check + call

Compare the name extracted from the uploaded result sheet with the login name. This reuses the
`verify_identity` verdict function from Lab 1, so first copy it into `lab6/identity.py`. You need only two
functions, `_edit_distance` and `verify_identity` (the `pdfplumber` and `boto3` code from Lab 1 is not
needed in the Streamlit image, so do not bring it over).

```bash
# Run inside lab6/ — create identity.py in the same directory as app.py
cat > identity.py << 'EOF'
def _edit_distance(a, b):
    """Levenshtein edit distance (standard DP)."""
    if a == b:
        return 0
    prev = list(range(len(b) + 1))
    for i, ca in enumerate(a, 1):
        cur = [i]
        for j, cb in enumerate(b, 1):
            cur.append(min(prev[j] + 1, cur[j - 1] + 1, prev[j - 1] + (ca != cb)))
        prev = cur
    return prev[-1]


def verify_identity(login_name, sheet_name):
    """Exact match passes / edit distance of 1 or less warns and continues / anything else blocks."""
    if not sheet_name:
        return "WARN"  # If the name could not be extracted, continue with a warning
    d = _edit_distance(login_name, sheet_name)
    if d == 0:
        return "PASS"
    elif d <= 1:
        return "WARN"
    return "BLOCK"
EOF
```

If you put `identity.py` in the **same directory** as `app.py` (`lab6/`), the

```python
import os

import urllib.request

REGION = "us-west-2"
DATA_BUCKET = os.environ.get("DATA_BUCKET", "")
GATEWAY_URL = os.environ.get("GATEWAY_URL", "")
RUNTIME_ARN = os.environ.get("RUNTIME_ARN", "")

s3 = boto3.client("s3", region_name=REGION)
agentcore = boto3.client("bedrock-agentcore", region_name=REGION)


def extract_via_gateway(s3_key, access_token):
    """Extract the result sheet through the Gateway MCP (calls the Lab 1 tool via the Gateway)."""
    payload = {
        "jsonrpc": "2.0", "id": 1, "method": "tools/call",
        "params": {
            "name": "bodyCompositionExtractor___extract_body_composition",
            "arguments": {"s3_key": s3_key},
        },
    }
    req = urllib.request.Request(
        GATEWAY_URL,
        data=json.dumps(payload).encode(),
        method="POST",
        headers={
            "Content-Type": "application/json",
            "Accept": "application/json, text/event-stream",
            "Authorization": f"Bearer {access_token}",
        },
    )
    with urllib.request.urlopen(req, timeout=60) as r:
        body = r.read().decode()

    # The response can be JSON or SSE (data: ...) format (see Lab 1 verify_gateway_mcp.py)
    obj = json.loads(body) if body.strip().startswith("{") else None
    if obj is None:
        for line in body.splitlines():
            if line.strip().startswith("data:"):
                obj = json.loads(line.strip()[5:])
                break
    text = obj["result"]["content"][0]["text"]
    return json.loads(text)


def invoke_supervisor(measurement, user_sub, session_id):
    """Call the Lab 5 Runtime (Supervisor) and get the coaching result."""
    resp = agentcore.invoke_agent_runtime(
        agentRuntimeArn=RUNTIME_ARN,
        contentType="application/json",
        payload=json.dumps({
            "prompt": json.dumps({
                "measurement": measurement,
                "user_sub": user_sub,
                "session_id": session_id,
            }, ensure_ascii=False)
        }),
    )
    return json.loads(resp["response"].read())


uploaded = st.file_uploader("Upload a body composition result sheet (PDF)", type="pdf")
if uploaded is not None:
    with st.spinner("Extracting values from the result sheet..."):
        s3_key = f"measurements/upload-{uuid.uuid4().hex}.pdf"
        s3.put_object(Bucket=DATA_BUCKET, Key=s3_key, Body=uploaded.getvalue())

        # Take the access token and use it for the Gateway call
        # TODO ④: Take the exposed access token
        access_token = st.user.tokens["________"]
        extracted = extract_via_gateway(s3_key, access_token)

    if extracted.get("status") not in ("OK", "VALIDATION_FAILED"):
        st.error(f"Extraction failed: {extracted.get('status')}")
        st.stop()

    measurement = extracted["measurement"]
    sheet_name = measurement.get("name")

    # TODO ③: Get the identity check verdict by comparing the login name with the sheet name
    from identity import verify_identity   # Reuses the Lab 1 edit-distance verdict
    verdict = verify_identity(display_name, ________)

    if verdict == "BLOCK":
        st.error("The name on the uploaded sheet does not match the logged-in user. You can only analyze your own result sheet.")
        st.stop()
    elif verdict == "WARN":
        st.warning("The name on the sheet differs slightly from the logged-in user (the scan may have been misread). Confirm that this is your own sheet.")

    st.success("Identity check passed. Requesting the analysis.")
    with st.spinner("The Supervisor agent is analyzing (this takes tens of seconds)..."):
        # Do not pass the name to the agent (boundary design) — pass only the measurement
        safe_measurement = {k: v for k, v in measurement.items() if k != "name"}
        result = invoke_supervisor(
            safe_measurement,
            user_sub=st.user.get("sub", "unknown"),
            session_id=f"session-{time.strftime('%Y-%m-%d')}",
        )

    st.markdown(result.get("result", "No result"))
```

### Step 5: Create the ECS Express Mode service

Express Mode requires 2 execution roles and the ECS service-linked role (Service-Linked Role).
If your account does not have them, create them once with the commands below.

```bash
# ECS service-linked role — used when ECS creates and manages service resources on your behalf
aws iam create-service-linked-role \
  --aws-service-name ecs.amazonaws.com 2>/dev/null || true
```

> If you see `InvalidInput: Service role name AWSServiceRoleForECS has been taken`, the role already
> exists, so this is normal. The purpose of this command is to create the role only when it is missing. After it,
> check the two execution roles below and run `create-express-gateway-service`.

```bash
# Task Execution Role — pulls the image and writes logs
aws iam create-role --role-name ecsTaskExecutionRole \
  --assume-role-policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"Service":"ecs-tasks.amazonaws.com"},"Action":"sts:AssumeRole"}]}' 2>/dev/null || true
aws iam attach-role-policy --role-name ecsTaskExecutionRole \
  --policy-arn arn:aws:iam::aws:policy/service-role/AmazonECSTaskExecutionRolePolicy

# Infrastructure Role — Express configures the ALB and autoscaling
aws iam create-role --role-name ecsInfrastructureRoleForExpressServices \
  --assume-role-policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"Service":"ecs.amazonaws.com"},"Action":"sts:AssumeRole"}]}' 2>/dev/null || true
aws iam attach-role-policy --role-name ecsInfrastructureRoleForExpressServices \
  --policy-arn arn:aws:iam::aws:policy/service-role/AmazonECSInfrastructureRoleforExpressGatewayServices

# The managed policy lacks ec2:DescribeAccountAttributes, so Express fails with AccessDenied
# at the step that checks the default VPC (confirmed by measurement). Fill the gap with an inline policy.
aws iam put-role-policy --role-name ecsInfrastructureRoleForExpressServices \
  --policy-name express-describe-account-attributes \
  --policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Action":"ec2:DescribeAccountAttributes","Resource":"*"}]}'

# Task Role — different from the two roles above. ecsTaskExecutionRole is used by the ECS agent
# (image pull, log shipping). The Task Role is used when the app.py code inside the container calls
# AWS APIs directly with boto3 (saving the Gateway extraction result, calling the Lab 5 Runtime).
# Express Mode does not create a Task Role automatically (taskRoleArn is None after creation), so you
# must create one yourself and attach it.
aws iam create-role --role-name bca-frontend-task-role \
  --assume-role-policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"Service":"ecs-tasks.amazonaws.com"},"Action":"sts:AssumeRole"}]}' 2>/dev/null || true

DATA_BUCKET=$(aws cloudformation describe-stacks --stack-name bca-workshop-core \
  --region us-west-2 --query 'Stacks[0].Outputs[?OutputKey==`DataBucketName`].OutputValue' --output text)

# ARN of the Runtime deployed in Lab 5 — app.py uses it when calling invoke_agent_runtime
# Caution: even if you create it with agentcore create --name BcaWorkshop, the deployed agentRuntimeName
# has a suffix and looks like `BcaWorkshop_BcaWorkshop-<hash>` (confirmed by measurement). An exact-match
# condition cannot find it, so search with contains.
RUNTIME_ARN=$(aws bedrock-agentcore-control list-agent-runtimes --region us-west-2 \
  --query "agentRuntimes[?contains(agentRuntimeName, 'BcaWorkshop')].agentRuntimeArn" --output text)
echo "RUNTIME_ARN=$RUNTIME_ARN"
# If the result has several lines (older revisions remain after a redeploy), pick only the latest one
# and store it in the shell variable, without a comma. Example: RUNTIME_ARN=$(echo "$RUNTIME_ARN" | tail -1)

aws iam put-role-policy --role-name bca-frontend-task-role \
  --policy-name frontend-agent-access \
  --policy-document '{
    "Version": "2012-10-17",
    "Statement": [
      {"Effect": "Allow", "Action": "bedrock-agentcore:InvokeAgentRuntime", "Resource": "*"},
      {"Effect": "Allow", "Action": "s3:PutObject", "Resource": "arn:aws:s3:::'"$DATA_BUCKET"'/measurements/*"}
    ]
  }'
```

Create the service. Streamlit uses port 8501, and the health check path is `/_stcore/health`.
You must specify `--task-role-arn` so that `app.py` can call the Gateway and the Runtime.

Also pass `DATA_BUCKET` and `RUNTIME_ARN`, which `app.py` reads through `os.environ`, as container environment variables.

```bash

  --region us-west-2 --query 'Stacks[0].Outputs[?OutputKey==`GatewayUrl`].OutputValue' --output text)

aws ecs create-express-gateway-service \
  --service-name bca-frontend \
  --primary-container "{\"image\":\"$IMAGE\",\"containerPort\":8501,\"environment\":[{\"name\":\"DATA_BUCKET\",\"value\":\"$DATA_BUCKET\"},{\"name\":\"GATEWAY_URL\",\"value\":\"$GATEWAY_URL\"},{\"name\":\"RUNTIME_ARN\",\"value\":\"$RUNTIME_ARN\"}]}" \
  --execution-role-arn "arn:aws:iam::$ACCOUNT:role/ecsTaskExecutionRole" \
  --infrastructure-role-arn "arn:aws:iam::$ACCOUNT:role/ecsInfrastructureRoleForExpressServices" \
  --task-role-arn "arn:aws:iam::$ACCOUNT:role/bca-frontend-task-role" \
  --health-check-path "/_stcore/health" \
  --monitor-resources \
  --region us-west-2
# When the status becomes ACTIVE, the service URL is returned. The URL prefix is not the service name
# but a `bc-<hash>` form that Express adds (measured example):
#   https://bc-00fcb754df8d4f21ade08f2e3542727e.ecs.us-west-2.on.aws/
```

> error, try again after about 1 minute.

> **If you edited the Dockerfile and pushed the image again** — pushing to the same `:latest` tag

> `DATA_BUCKET`, `GATEWAY_URL`, and `RUNTIME_ARN` all disappear. Always pass both parameters
> together when you redeploy.
>
> ```bash
> aws ecs update-express-gateway-service \
>   --service-arn "$SERVICE_ARN" \
>   --primary-container "{\"image\":\"$IMAGE\",\"containerPort\":8501,\"environment\":[{\"name\":\"DATA_BUCKET\",\"value\":\"$DATA_BUCKET\"},{\"name\":\"GATEWAY_URL\",\"value\":\"$GATEWAY_URL\"},{\"name\":\"RUNTIME_ARN\",\"value\":\"$RUNTIME_ARN\"}]}" \
>   --task-role-arn "arn:aws:iam::$ACCOUNT:role/bca-frontend-task-role" \
>   --region us-west-2
> ```
>
> After you redeploy, always check with the command below that the environment variables and the Task Role were actually applied.
>
> ```bash
> aws ecs describe-express-gateway-service \
>   --service-arn "$SERVICE_ARN" --region us-west-2 \

> ```

### Step 6: Update the callback URL

Update the Cognito callback to the URL that Express issued. You cannot know the URL before deployment, so
update the stack parameter after deployment.

The service URL is included in the output of `create-express-gateway-service` in Step 5. To check it again
later, use `describe-express-gateway-service`. This command takes **`--service-arn`**, not the service name.

> **Caution**: Express services do not show up in `aws ecs list-services` (the regular ECS cluster
> API path does not apply, so you get `ClusterNotFoundException` — confirmed by measurement). Instead, the service ARN follows a
> fixed rule set at creation time (`arn:aws:ecs:<Region>:<account-ID>:service/default/<service-name>`),
> so you can assemble it yourself if you know your account ID and the name you gave with `--service-name`.

```bash
# Assemble the service ARN (list-services does not return it, so build it from the fixed rule)
ACCOUNT=$(aws sts get-caller-identity --query Account --output text)
SERVICE_ARN="arn:aws:ecs:us-west-2:$ACCOUNT:service/default/bca-frontend"

# Look up the service URL (or copy it from the Step 5 create output)
# The URL is not in service.url but in ingressPaths[].endpoint of the active configuration
APP_URL=$(aws ecs describe-express-gateway-service \
  --service-arn "$SERVICE_ARN" --region us-west-2 \
  --query 'service.activeConfigurations[0].ingressPaths[0].endpoint' --output text)

# The endpoint value is sometimes returned without a scheme (host name only) (confirmed by measurement).
# A Cognito CallbackURL requires a scheme, so add https:// if it is missing.
case "$APP_URL" in
  https://*) ;;
  *) APP_URL="https://$APP_URL" ;;
esac
echo "$APP_URL"   # Example: https://bc-00fcb754df8d4f21ade08f2e3542727e.ecs.us-west-2.on.aws

# TODO ⑥: Update the callback URL parameter to the real service URL (the path is /oauth2callback)
aws cloudformation deploy \
  --template-file infra/01-core.yaml \
  --stack-name bca-workshop-core \
  --capabilities CAPABILITY_NAMED_IAM \
  --region us-west-2 \
  --parameter-overrides ________="$APP_URL/oauth2callback"
```

```python
verdict = verify_identity(display_name, sheet_name)
```

**TODO ④ — Extract the access token**

```python
access_token = st.user.tokens["access"]
```

The exposed tokens are not top-level keys of `st.user`. They are inside **`st.user.tokens`**. Use the name you put in `expose_tokens` (`access`) as the key. `st.user.get("access")` always returns `None`, which shows up as `has_token` being `false`.

**TODO ⑤ — Container port**

```dockerfile
EXPOSE 8501
```

The Streamlit default port is 8501. `--server.port=8501`, the Express `containerPort` 8501, and
`EXPOSE 8501` must all be the same for the load balancer to reach the container.

**TODO ⑥ — Update the callback parameter**

```python
--parameter-overrides HostedCallbackUrl="$APP_URL/oauth2callback"
```

Update `HostedCallbackUrl` to the ECS Express service URL you got after deployment. The path is
`/oauth2callback`, and the URL format is `https://<service-name>.ecs.us-west-2.on.aws`.
